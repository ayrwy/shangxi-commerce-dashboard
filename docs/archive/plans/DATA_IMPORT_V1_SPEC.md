# 商析数据导入第一版实施文档

> 版本：v0.1
> 更新时间：2026-07-25
> 适用范围：首版 Demo 的 CSV 导入、预览、字段确认和指标能力提示

## 1. 文档目的

本文件把数据导入页从“文件上传演示”定义为一条可以开发、联调和验收的最小闭环：

```text
选择/拖入 CSV
  -> 文件检查
  -> CSV 解析与预览
  -> 文件角色建议
  -> 字段确认
  -> 表关系与数据质量提示
  -> 指标能力清单
  -> 进入看板或保留为 Demo 数据
```

第一版重点是让用户知道：

1. 文件是否被正确读取；
2. 系统把每个文件识别成了什么；
3. 哪些指标可以计算，哪些不能计算以及原因；
4. 用户确认的配置是否真正保存。

第一版不要求接入后端、DuckDB 或外部平台 API，但页面不得用固定假文件冒充用户上传结果。

## 2. 第一版范围

### 2.1 必须完成

- 批量选择多个 CSV；
- 支持拖放上传，或明确只提供“选择文件”文案；
- 文件大小、名称、读取状态、行数、列数展示；
- UTF-8 CSV 的可靠解析，支持引号和字段内逗号；
- 表头、前 5 行数据、解析警告展示；
- 用户行为单表和订单多表两种导入路径；
- 根据实际上传文件生成字段确认列表；
- 文件角色和字段映射可修改并保存；
- 显示指标可用性和缺失字段原因；
- 空状态、读取中、解析失败、超限等状态；
- 下载至少一个用户行为 CSV 示例模板和一个订单多表模板；
- 刷新或返回页面时，在本次会话内保留导入配置；
- 构建通过，桌面端和窄屏可用。

### 2.2 第一版明确不做

- 自动接入淘宝、京东、抖音等官方 API；
- 任意复杂数据库关系的全自动推断；
- 浏览器端处理无限大小文件；
- 自动修复所有脏数据；
- 用 AI 直接计算指标；
- 上传数据直接替换现有模拟看板的完整计算链路。

如果首版看板仍由模拟数据驱动，界面必须明确标注“当前看板使用示例数据，上传文件仅完成结构预览”，不能让用户误以为上传数据已用于计算。

## 3. 页面和导航

数据导入拆成三个连续阶段，使用同一个 `ImportSession`：

### 3.1 文件上传页

显示：

- 上传区域；
- 文件队列；
- 每个文件的状态、大小、行数、列数；
- 解析错误和警告入口；
- “继续配置字段”按钮；
- “下载示例模板”入口。

按钮规则：

- 没有文件：继续按钮禁用；
- 有文件但仍在读取：继续按钮禁用；
- 存在解析错误：允许用户移除错误文件后继续，不能静默跳过；
- 只有警告：允许继续，但在下一步显示警告摘要。

### 3.2 字段确认页

每个实际上传文件显示：

- 原始文件名；
- 建议文件角色；
- 置信度；
- 可修改的角色下拉框；
- 推荐字段映射；
- 缺失字段和未识别字段；
- 表头及前几行预览入口。

页面顶部显示本次导入模式：

- `用户行为单表模式`；
- `订单多表模式`；
- `自定义/不完整模式`。

### 3.3 导入结果页或结果区

显示：

- 文件关系检查结果；
- 数据质量摘要；
- 指标能力清单；
- “返回修改字段”；
- “进入经营看板”；
- 若尚未接入真实计算，明确显示“看板继续使用示例数据”。

## 4. 核心数据结构

状态应提升到 `App` 或独立的 `importSession` 状态，不得只保存在上传页组件内部。

```ts
type FileStatus =
  | 'queued'
  | 'reading'
  | 'ready'
  | 'warning'
  | 'error'

type CsvPreview = {
  headers: string[]
  rows: string[][]
  totalRows: number
  delimiter: ',' | ';' | '\t'
  encoding: 'utf-8' | 'gb18030' | 'unknown'
  parseWarnings: string[]
  parseErrors: string[]
}

type ImportedFile = {
  id: string
  file: File
  name: string
  size: number
  lastModified: number
  status: FileStatus
  preview?: CsvPreview
  error?: string
}

type FileRole =
  | 'behavior'
  | 'orders'
  | 'order_items'
  | 'products'
  | 'users'
  | 'refunds'
  | 'unknown'

type FieldMapping = {
  source: string
  canonical: string
  confidence: 'high' | 'medium' | 'low' | 'manual'
}

type FileMapping = {
  fileId: string
  role: FileRole
  fields: FieldMapping[]
  confirmed: boolean
}

type MetricCapability = {
  key: string
  label: string
  available: boolean
  reason?: string
  requiredFields?: string[]
}

type ImportSession = {
  files: ImportedFile[]
  mappings: FileMapping[]
  mode: 'behavior' | 'orders' | 'custom'
  capabilities: MetricCapability[]
  confirmed: boolean
}
```

文件列表必须使用 `id` 作为 React key、读取更新和删除依据，不能使用文件名作为唯一标识。

## 5. 文件接收与解析规则

### 5.1 接收前检查

逐个文件检查：

| 检查项 | 规则 | 结果 |
|---|---|---|
| 扩展名 | `.csv`，大小写不敏感 | 非 CSV 直接拒绝 |
| 单文件大小 | 首版建议不超过 50 MB | 超限错误 |
| 总大小 | 首版建议不超过 200 MB | 超限错误 |
| 空文件 | 大小为 0 或无有效内容 | 错误 |
| 重复文件 | `name + size + lastModified` 相同 | 提示并跳过重复 |
| 文件数量 | 首版建议不超过 20 个 | 超限提示 |

### 5.2 解析要求

使用可靠的 CSV 解析器，不使用 `split(',')` 作为正式解析方案。第一版至少支持：

- UTF-8；
- UTF-8 BOM；
- 字段被双引号包裹；
- 字段值包含逗号；
- 空值；
- Windows 和 Unix 换行；
- 自动识别逗号、分号、Tab 三种常见分隔符。

GBK/GB18030 文件如果第一版不能稳定自动识别，必须提供“编码读取失败，请另存为 UTF-8”的明确提示，不能静默显示乱码。

### 5.3 表头和预览

首版默认第一行作为表头；如果第一行没有字段名，显示错误。对常见平台导出文件，可提供“选择表头行”的简单入口，但不要求自动处理所有报表格式。

预览至少包含：

- 字段名；
- 前 5 行；
- 总行数；
- 总列数；
- 分隔符和编码；
- 解析错误数和警告数。

如果每行列数不一致，状态为 `warning` 或 `error`，并展示前几条异常行号。

## 6. 文件状态机

```text
queued -> reading -> ready
                   -> warning
                   -> error
```

状态含义：

- `queued`：已进入队列，尚未开始解析；
- `reading`：正在解析；
- `ready`：解析完成且无阻断问题；
- `warning`：解析完成，但存在可继续的问题；
- `error`：无法用于字段确认，必须修复或移除。

“继续配置字段”只有在以下条件满足时可用：

```ts
files.length > 0 &&
files.every(file => file.status === 'ready' || file.status === 'warning')
```

## 7. 文件角色识别

角色识别只做规则推荐，最终由用户确认。推荐依据包括文件名、字段名和样例值。

### 7.1 用户行为明细表

推荐字段：

```text
user_id, goods_id, category_id, behavior, datetime, price, amount
```

行为值允许存在常见变体，界面应给出映射建议：

```text
buy: buy / purchase / payment / 支付 / 购买
pv: pv / view / click / 浏览
fav: fav / favorite / 收藏
cart: cart / add_cart / 加购
```

没有 `order_id` 时，所有“订单量”文案必须改为“购买行为数”。

### 7.2 订单主表

推荐字段：

```text
order_id, user_id, created_at, order_amount, status, channel
```

可支持 GMV、订单量、客单价、购买用户数和渠道贡献，具体以字段能力清单为准。

### 7.3 订单商品明细

推荐字段：

```text
order_id, product_id, product_name, quantity, price
```

用于商品销售额、销量和商品排行。

### 7.4 商品、用户、退款表

分别识别：

- 商品：`product_id`、商品名、类目、价格；
- 用户：`user_id`、注册时间、来源、会员等级；
- 退款：`order_id`、退款金额、退款时间、退款原因。

缺少某类文件时不报“导入失败”，而是在指标能力清单中说明受影响的模块。

## 8. 两种导入路径

### 8.1 用户行为单表模式

当只有一张包含 `behavior` 的明细表，或用户手动将文件确认成行为表时，进入该模式。

指标口径：

```text
GMV = sum(price * amount), behavior = buy
购买件数 = sum(amount), behavior = buy
购买用户数 = distinct user_id, behavior = buy
购买行为数 = count(rows), behavior = buy
漏斗 = pv -> fav -> cart -> buy
```

限制：

- 无 `order_id`：不称为真实订单量；
- 无退款字段：退款率显示“暂无数据”；
- 无渠道字段：渠道贡献显示“暂无数据”；
- 无有效时间字段：不能提供日期趋势。

### 8.2 订单多表模式

只要检测到订单主表、订单明细表或用户明确选择订单角色，即进入订单模式。

必须检查的关系：

```text
orders.order_id -> order_items.order_id
orders.user_id -> users.user_id
order_items.product_id -> products.product_id
refunds.order_id -> orders.order_id
```

指标粒度必须固定：

- 订单量、订单 GMV：订单主表粒度；
- 商品销量、商品销售额：订单明细粒度；
- 退款金额、退款率：退款粒度或订单退款汇总粒度；
- 用户指标：用户/订单关系粒度。

多表关联后不得直接对重复的订单金额求和。

## 9. 数据质量检查

### 9.1 错误：阻止继续

- 文件为空；
- 没有表头；
- 无法解析 CSV；
- 没有任何可识别字段；
- 文件超过大小限制；
- 所有数据行列数都不一致；
- 选择订单模式但没有任何订单标识或金额字段。

### 9.2 警告：可以继续，但要说明影响

- 必填字段部分为空；
- 日期存在无法解析的值；
- 金额包含货币符号或千分位，系统进行了清洗；
- 存在重复行；
- 外键匹配率偏低；
- 同一订单多行且订单金额重复；
- 文件时间范围与其他文件不一致。

### 9.3 提示：自动处理并记录

- 去除 UTF-8 BOM；
- 忽略末尾空行；
- 统一字段名前后空格；
- 将常见金额格式转换为数值；
- 将常见行为值映射为标准行为。

## 10. 指标能力清单

字段确认完成后生成能力清单，不能显示无依据的数字。

首版至少检查：

| 指标 | 最小条件 | 缺失时文案 |
|---|---|---|
| GMV | 行为模式有 `behavior + price + amount`，或订单模式有订单金额 | 暂无 GMV：缺少成交金额字段 |
| 订单量 | 订单模式有 `order_id` | 暂无真实订单量：缺少 order_id |
| 购买行为数 | 行为模式有 `behavior` | 暂无购买行为数：缺少行为字段 |
| 购买用户数 | `user_id` + buy 行为或订单用户字段 | 暂无购买用户数：缺少 user_id |
| 商品排行 | 商品明细有商品标识和数量/金额 | 暂无商品排行：缺少商品明细 |
| 渠道贡献 | 有渠道字段 | 暂无渠道贡献：缺少 channel |
| 退款率 | 有退款字段或退款表 | 暂无退款率：缺少退款数据 |
| 复购率 | 有 user_id 和可排序时间 | 暂无复购率：缺少用户或时间字段 |
| 行为漏斗 | 有标准化 behavior | 暂无行为漏斗：缺少行为字段 |

## 11. 关键交互文案

推荐统一使用明确动词：

- “选择 CSV 文件”；
- “拖入 CSV 文件”；
- “查看预览”；
- “移除文件”；
- “重试解析”；
- “确认字段映射”；
- “返回修改”；
- “查看缺失字段”；
- “进入经营看板”。

错误文案必须解释原因和下一步，例如：

> `orders.csv` 读取失败：检测到 GBK 编码。请将文件另存为 UTF-8 CSV 后重试。

不要只显示“解析失败”或让用户看到空白区域。

order_id,product_id,product_name,quantity,price

## 13. 开发拆分

6. 增加错误、警告和重试/移除交互；

### P1：首版交付前完成

3. 表关系匹配率提示；
4. 拖放上传；

6. 窄屏布局和键盘焦点检查；

## 14. 验收用例

### 用例 A：正常上传两个 UTF-8 CSV

- 选择订单主表和订单明细；
- 两个文件分别显示行数、列数和前 5 行；
- 字段确认页显示真实文件名和推荐角色；
- 修改字段映射后离开再返回，配置仍存在；
- 显示订单指标和商品指标可用。

### 用例 B：只有用户行为单表

- 上传包含 `behavior` 的单表；
- 自动推荐用户行为明细表；
- 显示 GMV、购买件数、购买用户数和行为漏斗可用；
- 订单量显示为“购买行为数”；
- 退款率和渠道贡献显示暂无数据及原因。

### 用例 C：带引号和字段内逗号

- 商品名为 `"桌子,原木色"`；
- 列数和预览字段保持正确；
- 不产生额外列。

### 用例 D：解析失败

- 上传空文件或无表头文件；
- 文件状态显示错误；
- 继续按钮不可用；
- 用户可以移除文件或重试，不出现空白页。

### 用例 E：同名文件

- 上传两个同名但不同大小的文件；
- 两个文件拥有不同 ID；
- 可分别预览、删除和显示状态。

### 用例 F：重复订单金额

- 订单主表与明细表关联后订单金额重复；
- 显示数据质量警告；
- 指标能力清单说明 GMV 按订单粒度计算。

### 用例 G：未完成解析时点击继续

- 大文件处于读取中；
- 继续按钮保持禁用；
- 所有文件完成后按钮才可用。

### 用例 H：看板边界

- 完成字段确认后进入看板；
- 如果尚未接入真实计算，页面显示“示例数据运行中”；
- 不把上传文件的行数或文件名伪装成看板计算结果。
